#価値内容見せる場面
1非構造化データもテーブルと同じように扱える音声やPDFも、テーブルと同じ場所に置いて、同じSQLで扱えます。Part1：通話・PDFをステージに置き、AI_TRANSCRIBE／AI_PARSE_DOCUMENT でテーブル化（UC5 の店舗報告PDFも）
2大量の非構造化データを、Cortex AIで簡単に分析できる形にこれまで非構造化データは構造化データのように分析することが困難でした。Cortex AIなら大量の音声や文書から日時・数値・個人情報などを取り出して構造化データに変換でき、通常のデータと同じ感覚で集計・可視化できます。Part2：通話から AI_COMPLETE で種別・感情・解約リスクを抽出、AI_REDACT でマスク。ダッシュボード（UC1）の通話系タイルの元データ
3Cortex Searchは「属性で絞り込める検索」チャンク分割した文書に属性（種別・日付・カテゴリなど）を付けて、条件で絞り込んで検索できます。属性はアプリのフィルタ機能にもそのまま使えます。UC3（同じ質問を3通りで検索）、シーン1・2（Agent が属性フィルタを自動で組み立てる）、UC4（フィルタを固定したツール）
4セマンティックビューは画面操作だけで作れて、精度も高いAutopilotを使えば、SQLを書かずに数分で作成できます。自然言語での質問にも正確に答えます。Part4：Autopilot で作成。シーン4（ロット×解約リスク×会員ランクの集計）の数値を支える
5Cortex Agentでノーコードに近いAIアシスタントを作り、社内公開設定は宣言型で、ツールの使い分けは自然言語で指示するだけ。リフレクションは自動、データには利用者本人の権限でアクセスします。AnalystとCortex Searchを組み合わせ、数値データと文書をまたいで回答します。UC2（シーン1〜4）。シーン4では SQL エラーを自動で直して再実行した（リフレクション）。UC4（権限デモ）
6ダッシュボードを指示するだけで作り、その場で考察できるCoCoに簡単に指示するだけでHTMLレポートやApp Runtimeのアプリを作成。CoWorkのアーティファクトに登録すれば、ダッシュボードについて自然言語で質問・考察できます。UC1（プロンプト1回で Snowflake Dashboards を作成）→ UC2（CoWork でタイルに追加質問）
7CoCoがあれば、ハンズオン後も自分で使いこなせるCoCo（Cortex Code）はSnowflakeを熟知したAIのパートナー。質問、SQLやアプリの作成、エラー解決まで手伝ってくれるので、学んだことを自社データに当てはめるときも自分で進められます。全パートで「困ったらCoCoに聞く」を実演。ダッシュボード作成（UC1）も CoCo で行う

UC3：同じ質問を3通りで検索する

回フィルタヒットした文書（上位3件、検証結果）返ってくる内容
①なし（全件）FAQ 1件＋お客様都合の返品の通話2件お客様向けの説明と通話記録が混ざる
②audience = 社外公開FAQ のみ「お客様都合は到着後7日以内、不良品は14日以内・送料当社負担」
③department = カスタマーサポート部 かつ audience = 社内限定 かつ 通話以外マニュアル2件＋特例対応通達「対象ロットは期限なし（2027年3月31日まで）・交換を優先・集荷も当社手配・500円クーポン」
-- ③ の例
SELECT SNOWFLAKE.CORTEX.SEARCH_PREVIEW('KNOWLEDGE_SEARCH', '{
  "query": "返品できますか",
  "columns": ["CHUNK_TEXT", "DOC_TYPE", "TITLE"],
  "filter": {"@and": [
    {"@eq": {"DEPARTMENT": "カスタマーサポート部"}},
    {"@eq": {"AUDIENCE": "社内限定"}},
    {"@not": {"@eq": {"DOC_TYPE": "通話"}}}
  ]},
  "limit": 3
}');

既存の FAQ と社内マニュアルは返品条件が同じ（不良品は14日以内・送料当社負担）だったため、差を作る文書として「特例対応通達」（CS部・社内限定）を追加した。通話にも CS部・社内限定を付けているため、③では「通話以外」（@not）の条件が必要。

ダッシュボードのフィルタと Cortex Search のフィルタの違い

どちらも「照明」「10月以降」で絞れるため同じように見えるが、絞り込む対象が違う。Cortex Search のフィルタは、通話やPDFといった非構造化データの文章そのものを絞り込む。

ダッシュボードのフィルタCortex Search のフィルタ（属性）
絞り込む対象構造化テーブルの行（FACT_ORDERS の注文、CALL_ANALYSIS の通話件数）通話の文字起こしやPDFを分割した文章の断片（チャンク）
返ってくるもの集計した数字（返品率 15.4% など）文章そのもの（「点灯10分ほどでちらつく」「対象ロットは期限なし」など）
絞り込みの条件テーブルにもともとある列（注文日、商品カテゴリ）文章に後から付けた属性。PDF の属性（文書の種類・部署・公開範囲・発行日・対象商品）は文書の表紙から、通話の属性（商品カテゴリ・感情）は会話の中身から、すべて AI_COMPLETE で取り出す
使いどころ「何が起きているか」を数字で見る「なぜ起きているか」「どう対応するか」を文書と通話から探す
絞らないとどうなるか全期間・全カテゴリの数字になるお客様向けFAQと社内通達、過去の通話が混ざり、間違った案内につながる（UC3 の①）

例：品質報告書PDFのチャンク1件（本文は検索の対象、下のタグがフィルタに使う属性）

「返品回収品12台を分解調査した結果、全数でLEDドライバ基板のコンデンサに容量抜けを確認した。不具合品はすべて2026年9月入荷のロット LOT-2609-B に属しており…」

DOC_TYPE: 品質報告DEPARTMENT: 品質管理部AUDIENCE: 社内限定DOC_DATE: 2026-10-15PRODUCT_CATEGORY: 照明PRODUCT_IDS: [PRD-LGT-0001]

CoWork では、Agent が質問からこの属性フィルタを自分で組み立てる。当日は、回答の「思考過程」で実際に使われたフィルタを見せると、「文章を属性で絞った」ことが伝わりやすい。検証時の実例：{"@and":[{"@eq":{"PRODUCT_CATEGORY":"照明"}},{"@eq":{"DOC_TYPE":"通話"}},{"@gte":{"DOC_DATE":"2026-10-01"}}]}

属性は手で作らず、すべて AI_COMPLETE で非構造化データから取り出している。PDF 11本の属性は、用意した正解と全項目一致した（12章）。

5. CoWork のプロンプトと期待する回答

ダッシュボードを CoWork の artifact に登録して壁打ちする操作

  1. Snowsight の Workspaces で、CoCo が作ったダッシュボード（.dash ファイル）を開く

シーンごとのプロンプト

当日はこの順で一続きの会話として実演する想定です。「Agent の動き」と「回答」は、検証環境で DATA_AGENT_RUN を実行したときの実際の結果です。

シーン1：異変に気づく（ダッシュボードの「商品別 返品率」タイルから質問）
10月から照明カテゴリの返品率が上がっているのはなぜ？通話記録も調べて
  • Agent の動き：Analyst → Search（フィルタ PRODUCT_CATEGORY=照明 かつ DOC_DATE≥2026-09-15 を自分で組み立てた）→ ロット別の返品率を SQL で集計
  • 回答：「原因は LEDデスクライト 調光式のロット LOT-2609-B。返品率は9月 1.9% → 10月 36.1% → 11月 48.1%。他の照明は2〜4%で変化なし。通話の訴え（点灯10分ほどでちらつく）は品質報告の症状と一致」
  • データ上の件数：10月以降の不具合通話は28件（うち LOT-2609-B の LEDデスクライト 26件、うち同じ顧客からの再入電3件）
シーン2：原因を特定する
LEDデスクライトのちらつきについて、品質管理部は原因を把握していますか？
  • Agent の動き：Search（フィルタ DEPARTMENT=品質管理部 を自分で組み立てた）
  • 回答：「把握しています。第1報で、LEDドライバ基板のコンデンサの容量抜けが原因（仕入先の代替部品の耐熱不足）。対象は9月入荷の LOT-2609-B。10月14日に出荷停止」
  • 参考：固定フィルタで検索した場合も、doc_type=品質報告 かつ product_ids に対象商品を含む（@contains）で、第1報・第2報だけが返ることを確認済み
シーン3：案内方法を決める
LEDデスクライトを返品したいお客様には、どう案内すればいい？お客様向けの案内と、社内の対応手順を分けて教えて
  • Agent の動き：社内ナレッジ（AUDIENCE=社内限定 を自分で指定）と、お客様向けFAQツール（社外公開に固定）の両方を使用
  • お客様向け（FAQ）：「不良品は到着後14日以内に連絡、返送料は当社負担（着払い）」
  • 社内手順（特例対応通達）：「注文番号からロットを確認し、LOT-2609-B なら特例対応（期限なし・交換優先）、それ以外は通常の不良品対応」
シーン4：アクションにつなげる
ロット LOT-2609-B を買ったお客様で、通話の解約リスクが高い人は何人？会員ランク別に出して
  • Agent の動き：Analyst → SQL（対象ロットの購入者と、解約リスク「高」の通話を結合）
  • 回答：「購入者111人のうち解約リスク「高」は4人（silver 2人、standard 1人、gold 1人）」。さらに「判定された通話がこのロットの件かは未確認」と注意書きを付けた
この内容を、明日の品質会議向けに3行でまとめて

CoWork で確認済み（12章）。原因・CSの運用課題・会議で決めることの3行で返った

権限デモ（UC4・任意）

シーン3と同じ質問を、お客様窓口向けのロールで投げる。このロールでは「お客様向けFAQ」ツール（audience=社外公開 に固定）しか使えないため、社内手順は返らない。ツールにフィルタを固定できることは確認済み。ロールを切り替えたデモは未検証。

CREATE OR REPLACE CORTEX SEARCH SERVICE KNOWLEDGE_SEARCH
  ON CHUNK_TEXT
  ATTRIBUTES DOC_TYPE, DEPARTMENT, AUDIENCE, DOC_DATE, PRODUCT_CATEGORY, PRODUCT_IDS, SENTIMENT
  WAREHOUSE = GLACIERSTYLE_WH
  TARGET_LAG = '1 day'
  EMBEDDING_MODEL = 'snowflake-arctic-embed-l-v2.0'
AS SELECT CHUNK_ID, CHUNK_TEXT, TITLE, DOC_TYPE, DEPARTMENT, AUDIENCE, DOC_DATE,
          PRODUCT_CATEGORY, PRODUCT_IDS, SENTIMENT
   FROM KNOWLEDGE_CHUNKS;   -- 検証環境で作成できることを確認済み

Agent のツール設定（属性フィルタのための要点）

  • 社内ナレッジツール：columns_and_descriptions で属性列を filterable: true にし、取り得る値を説明に書く（例：「値: 通話, FAQ, マニュアル, 品質報告, 通達, 店舗報告」）。これで Agent が質問からフィルタを組み立てた
  • お客様向けFAQツール：同じサービスに filter: {"@eq": {"AUDIENCE": "社外公開"}} を固定

使うフィルタの一覧

場面フィルタ演算子

UC2 シーン1（固定で確認）通話 かつ 照明 かつ 10月以降 かつ ネガティブ@and, @eq, @gte
